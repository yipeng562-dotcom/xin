# 64DBG 调试助手

本机项目为 `E:\64DBG`，链路为 x64dbg → X64DbgContextV2.dp64 → TCP/JSONL → SnapshotAssistant64。技能复用现有程序，不包含二进制，也不提供新的远程调试控制接口。

## 按任务使用

- 启动或诊断接收器：读取 [本机操作参考](references/local-operations.md)，检查文件、已有进程与8768监听。用户要求启动且尚未运行时再启动，避免重复实例。
- 分析现场：优先使用用户提供的智能复制文本或当前会话新数据。回退文件仅含失败投递记录，不是完整实时流；缺少现场时，先检查相关日志，必要时请用户智能复制当前现场。
- 查询引用：使用参考中的x64dbg命令。确认当前目标地址，考虑ASLR，优先用当前模块基址加RVA定位。
- 修改工具源码：仅在用户要求开发或修复时，读取项目README、最新接续记录和相关源码，再构建测试。创建技能或读取现场不自动触发部署。

## 现场解读

1. 真实执行地址是 `rip`（兼容字段可能为 `eip`）；`selected_address` 是浏览位置。两者不同应分别说明CPU现场和静态浏览，不能认为CPU已执行到浏览处。`selection_equals_eip` 在本项目仍描述64位地址关系。
2. 同时检查 `debug_state`、`registers_valid` 和 `snapshot_consistent`。运行时界面可能保留最近有效暂停现场，不能把保留寄存器当成当前运行值。
3. 核对 `session_id`、序号、时间和TCP/fallback来源。CPU、浏览、运行状态可能乱序到达，不用最后一行或最大序号代表全部状态。重建状态时参考 `SnapshotAssistant64\SnapshotStore.cs`。
4. 地址保留64位十六进制，避免经浮点转换损失精度。栈采集16个QWORD，界面默认显示4个。CALL地址加指令长度只是理论返回地址，不代表调用已发生。
5. XREF独立于普通Snapshot。结果为空时检查 `error`，区分查询失败和未找到引用；静态引用不能证明运行时路径或调用次数。
6. XREF默认只参与下一次成功智能复制，右侧仍显示不代表下次还会复制。需要时使用“重新附带到下次复制”。`xref_only` 仅复制引用段，缺少CPU段不代表采集失败。
